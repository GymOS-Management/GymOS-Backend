# M3.3 Invoices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The invoices domain — `Invoice`/`InvoiceLine` aggregate, per-year DB-sequence numbering, issuing on assignment/trial-conversion/upgrade, net-sign proration with scheduled downgrades, mark-paid as the first production `IIdempotentCommand`, void with confirmation, and the frozen §3.4 endpoint surface.

**Architecture:** Mirrors M3.2's layering exactly: aggregate + transition table + rules in Platform.Domain; commands/handlers/queries-interfaces in Platform.Application; EF config, migration, repository, queries in Platform.Infrastructure; endpoints in the host. Proration is a pure domain calculator over `Money.Allocate`; issuing is an Application-layer service (`SuperAdminGuard` precedent) invoked inside the same save as the subscription change.

**Tech Stack:** existing only — .NET 10, EF Core + Npgsql, xUnit + Testcontainers. **No new packages.**

**Spec:** `docs/superpowers/specs/2026-08-08-invoices-design.md` (approved). Schema/endpoints frozen in `GymOS-Specification/ARCHITECTURE.md` §2.3/§3.4.

## Global Constraints

- Frozen architecture; two recorded property-preserving deviations only (per-amount currency columns; `pending_*` columns on gym_subscriptions). No others without stopping.
- R4: aggregates carry `Money`; DTOs/events carry `decimal Amount` + a property whose name contains `Currency` on a **record**. Never a naked money-decimal on a class.
- Events: `gymos.platform.invoice.<past-tense-action>` (R9 regex `^gymos\.[a-z0-9_]+\.[a-z0-9_]+\.[a-z0-9_]+$`; `paid` is on the irregular allow-list). Raised in aggregates only via `Raise(...)`.
- `IClock` only; time flows inward. Business failures are `Result` (`Error` factories); invariants are `DomainException`/`BusinessRules.Check`, mapped by handlers to `Error.Conflict("invoices.invalid_state", ex.Message)` (M3.2's exact pattern).
- One `SaveChangesAsync` per use case. Mark-paid rides the AD-39 explicit transaction automatically — no handler changes needed for that.
- Migrations: generate, then append documented `migrationBuilder.Sql(...)`; never hand-edit Designer/snapshot. `dotnet ef` needs the dockerized postgres (localhost:5432) up.
- Endpoints: `.RequireAuthorization(<permission const>)` + `.WithName` + `.WithSummary` + `.WithDescription` + `.Produces...` are ALL mandatory (EndpointConventionTests R11/R12).
- OpenAPI snapshot changes are deliberate: regenerate with `$env:UPDATE_OPENAPI_SNAPSHOT='1'; dotnet test tests/GymOS.IntegrationTests --filter "FullyQualifiedName~OpenApiContractTests"`, then review `git diff contracts/openapi-v1.json`, then unset the var.
- Test-run validity: output must contain no `Aborted` (known CLR crash truncates runs while printing `Passed!`). Known-good totals before this plan: SharedKernel 126 · BuildingBlocks 42 · Architecture 123 · Domain 242 · Application 147 · Infrastructure 67 · Integration 155 = **902**.
- Commands run from repo root. Commit messages end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- House style: file-scoped namespaces, doc comments on every public member, `[LoggerMessage]` on `sealed partial` for logging, `sealed` by default.

**`Proration.Compute` contract:** `totalDays = (int)Math.Ceiling((periodEnd - periodStart).TotalDays)`; `daysUsed = Math.Clamp((int)Math.Floor((now - periodStart).TotalDays), 0, totalDays)`; `daysRemaining = totalDays - daysUsed`; return null when `daysRemaining == 0`. `credit = oldPrice.Allocate(daysUsed, daysRemaining)[1]`; `charge = newPrice.Allocate(daysUsed, daysRemaining)[1]`; `net = charge.Add(Money.Of(-credit.Amount, credit.Currency))`. internal sealed class InvoiceNumberGenerator : IInvoiceNumberGenerator

    private readonly AppDbContext _dbContext;
    public InvoiceNumberGenerator(AppDbContext dbContext) => _dbContext = dbContext;

```csharp
            // ── Invoice numbering (frozen §2.3: sequential per year, DB sequence) ─────────
            // Raw SQL because EF has no notion of on-demand per-year sequences. Idempotent and
            // gap-tolerant: a rolled-back issuing transaction burns a number (flagged for counsel
            // in docs/BusinessRules/Invoices.md). Callers: InvoiceNumberGenerator today; the M3.4
            // renewal job through the same class later.
            migrationBuilder.Sql(
                """
                CREATE OR REPLACE FUNCTION platform.next_invoice_number(p_year integer)
                RETURNS bigint
                LANGUAGE plpgsql
                AS $function$
                DECLARE
                    sequence_name text := format('invoice_number_seq_%s', p_year);
                BEGIN
                    IF NOT EXISTS (
                        SELECT 1 FROM pg_sequences
                        WHERE schemaname = 'platform' AND sequencename = sequence_name)
                    THEN
                        EXECUTE format('CREATE SEQUENCE IF NOT EXISTS platform.%I', sequence_name);
                    END IF;
                    RETURN nextval(format('platform.%I', sequence_name));
                END;
                $function$;
                """);

            // ── One currency per invoice (design deviation record: three Money columns replace
            // §2.3's single currency column because R4 forbids naked decimals; this CHECK holds
            // the stated property the single column would have given for free) ────────────────
            migrationBuilder.Sql(
                """
                ALTER TABLE platform.invoices
                    ADD CONSTRAINT ck_invoices_single_currency
                    CHECK (subtotal_currency = tax_currency AND tax_currency = total_currency);
                """);
```

`Down` (before `DropTable`s): `migrationBuilder.Sql("DROP FUNCTION IF EXISTS platform.next_invoice_number(integer);");` — the constraint drops with its table; per-year sequences are cheap and left in place (comment saying so).
